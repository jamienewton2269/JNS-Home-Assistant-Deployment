# JNS Home Assistant Deployment Platform v5.5.0

## Added

- One-time Management PC enrollment codes.
- Per-PC registry under `/config/jns/management/`.
- Dedicated HA system identity/refresh token for each enrolled PC.
- Per-PC Ed25519 SFTP public-key authorization.
- Per-PC `config` publisher trust records.
- Management-PC list, commission and revoke services.
- Explicit legacy-credential revoke action gated on successful commissioning.
- JNS Secure SFTP v0.4.0 host public-key export for server fingerprint pinning.
- Fail-closed SFTP shutdown/clear behavior when the final authorized key is revoked.

## Preserved

- Existing pre-v5.5 SFTP keys and `jns-config-production` trust during migration.
- Existing admin-authenticated v5.4 management path until explicitly revoked.
- Signed package, configuration-check, transaction, rollback and audit protections.

## Security model

The enrollment endpoint is intentionally unauthenticated at the HTTP layer but requires a high-entropy, short-lived, single-use capability generated by an authenticated Home Assistant administrator. Only the capability hash is persisted. The endpoint accepts public keys only and returns a dedicated HA refresh token to the approved PC.

## v5.4.3 production fixes carried forward

- Supervisor repository readiness polling remains in place.
- Existing Supervisor repositories are explicitly refreshed before app discovery/update.
- SFTP app discovery waits for the app to become queryable instead of assuming immediate indexing.
- Provisioning failures retain stage-specific, sanitized diagnostics.
- JNS Secure SFTP remains a prebuilt architecture-specific GHCR image; Home Assistant does not build it locally.
- The v5.5 SFTP app image is published per architecture using the same proven workflow pattern introduced in v5.4.3.
